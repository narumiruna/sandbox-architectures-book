# リソースの上限 {#resource-limits}

[Resource limits](../../glossary/resource-limit.md) は、worker が使えるリソースの量を制限します。アクセスルールは、worker が何にアクセスできるかを制限します。ディスクの上限を設ければ、ビルドでストレージがいっぱいになるのを防げますが、別のプロジェクトのファイルへのアクセスを防げるのはアクセスルールだけです。

[Lamp の例](../design/from-issue-to-patch.md)では、worker に割り当てるリソースで、ビルド用ファイルの書き込みだけでなく、C プログラムのコンパイルとテストもまかなう必要があります。

## 上限を設定し、達したときの動作を決める {#set-a-budget-and-decide-what-happens-at-the-limit}

以下の上限は例であり、デフォルト値でも、測定した必要量でもありません。最初のコマンドだけでなく、コンパイラやテストの process も含め、worker 全体の使用量を計上します。[control plane](../../glossary/control-plane.md) は上限を設定し、作業の受け入れを判断して、期限を強制します。[runtime](../../glossary/runtime.md) は実行時のリソースに上限を設け、workspace サービスは一時ストレージを制限します。

| 制限の対象 | 上限の例 | 上限に達したときの動作 |
| --- | --- | --- |
| CPU | 各集計期間で、CPU 1 個分の実行時間までです。 | runtime は worker を停止せず、実行速度を落とします。この上限を設定しても、Lamp 専用の CPU が確保されるわけではありません。 |
| メモリ | VM のメモリは 256 MiB で、Linux と worker 内のすべての process が共有します。 | runtime がメモリ上限による失敗を報告したら、実行を停止します。条件を変えずに再試行しません。 |
| ディスク | 配置済みの入力や一時的なビルドファイルを含め、書き込み可能な `/work` ディスク全体で 64 MiB です。 | 上限を超える書き込みは失敗します。ディスク上限が原因でビルドが失敗した場合は、安全な理由コードを返し、途中まで作成されたファイルを破棄します。 |
| 時間 | キューでの待機、worker の起動、コマンドの実行にそれぞれ 30 秒を割り当て、個別に計測します。 | 期限に達したら、キュー内の要求を失効させるか、開始済みの試行を停止します。どの段階でタイムアウトしたかを記録します。 |
| 容量 | [tenant](../../glossary/tenant.md) ごとに、準備中とクリーンアップ中も含めて worker の割り当ては 1 つまで、追加の待機要求は 2 件までです。 | 空きがある場合にだけ要求をキューに入れます。枠を超える要求は拒否します。最初の Lamp worker が枠を占めている間は、2 つ目の worker を起動しません。 |

## 途中までの出力を成功とみなさない {#do-not-mistake-partial-output-for-success}

リンク処理中に Lamp がディスク上限に達すると、不完全なバイナリが残り、テストが始まらないことがあります。失敗、キャンセル、タイムアウトで終わった試行では、途中までのパッチ、生のログ、バイナリではなく、ステータスと安全な理由コードを返します。どの上限が原因だったかは、その上限を強制する層が報告した場合にだけ記録します。control plane は worker を停止し、成功時と同じ[クリーンアップのルール](sandbox-lifecycle.md#what-gets-deleted-and-when)に従います。権限のある要求元は原因を解消した後、新しい試行を開始できます。同じ上限で自動的に再試行すると、同じ失敗を繰り返すことがあります。

collector は、別途[出力サイズの上限](../data-and-access/workspaces-and-artifacts.md#decide-what-leaves-work)を強制します。ビルドとテストが成功しても、エクスポートに失敗することがあります。この場合も、2 つそろわないまま公開しません。

次は[Observability とデバッグ](observability-and-debugging.md)です。上限に達した場合、アクセスが拒否された場合、ビルドが失敗した場合の見分け方を説明します。
