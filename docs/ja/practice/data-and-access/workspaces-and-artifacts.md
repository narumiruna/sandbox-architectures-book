# Workspace と artifact {#workspaces-and-artifacts}

worker にはプロジェクトのコピーを編集させ、レビュー担当者に必要なファイルだけを返させます。[Lamp の手順解説](../design/from-issue-to-patch.md)では、Linux worker が `/work` で修正をビルドしてテストします。レビュー用にテキスト形式のパッチとテスト出力を返すことはできますが、修正を公開することはできません。

## worker が変更できる範囲を決める {#choose-what-the-worker-can-change}

[workspace](../../glossary/workspace.md) は、ジョブが扱えるファイルの集まりです。[mount](../../glossary/mount.md) は、あるパスでファイルを利用できるようにする仕組みです。ファイルをコピーするとは限りません。チェックアウトは、リポジトリの特定のリビジョンに対応するソースツリーです。

| Workspace の選択肢 | 元のチェックアウトへの影響 | 適した用途 |
| --- | --- | --- |
| 読み取り専用 mount | worker はファイルを読み取れますが、その mount を通じて変更することはできません。編集には、別の書き込み可能な場所が必要です。他の process は元のファイルを変更できる場合があります。 | 内容の調査、またはすべての出力を別の場所に書き込むビルドです。 |
| 書き込み可能な共有ディレクトリ | そのディレクトリが元のチェックアウトであれば、編集、削除、途中までの書き込みがその場で元のファイルに反映されます。ジョブが失敗しても同じです。 | 変更をその場で反映することを意図した、信頼できるローカル環境での作業です。 |
| 明示的にエクスポートする使い捨てコピー | worker は自分のコピーだけを編集します。元のチェックアウトは mount されず、worker がそこに書き込める別の経路もありません。別の収集コンポーネントが受け入れたものだけが返ります。 | ソースを編集する必要がある一方、レビュー前には変更を適用してはならないビルドです。 |

読み取り専用でも、情報が非公開になるわけではありません。worker は mount で公開されたものをすべて読み取れます。どの方式でも、必要な入力だけを渡します。ローカル設定や [credentials](../../glossary/credential.md) は含めません。

## `/work` から何を取り出すか決める {#decide-what-leaves-work}

[Artifacts](../../glossary/artifact.md) は、ジョブの終了後に残すために選んだ出力です。Lamp のレビュー担当者に必要なのは、`change.patch`（最大 128 KiB）と `test.log`（最大 64 KiB）の 2 つだけです。この例の上限は、worker のディスク上限とは別に、受け入れる各ファイルに適用します。

1. workspace サービスは、[control plane](../../glossary/control-plane.md) がその実行に割り当てた内容に従います。承認済みリビジョンのソースとテスト、およびタスクの要約を、`/work` に mount した新しい [guest](../../glossary/guest.md) ディスクにコピーします。リポジトリの履歴、設定、シークレットはコピーせず、元のチェックアウトも mount しません。worker はテストも含めてコピーを変更できます。
2. ビルドとテストのコマンドが成功を報告し、worker が停止した後で、worker の [isolation boundary](../../glossary/isolation-boundary.md) の外にある収集コンポーネントが、その実行のディスクから指定された 2 ファイルだけを読み取ります。ファイルシステム上のリンクはたどらず、両方が上限内の通常の UTF-8 テキストファイルである場合に限り、セットで受け入れます。ファイルがない、サイズが上限を超える、または内容が形式上無効な場合は、出力の一部を公開するのではなく、結果を拒否します。実行 ID、基準リビジョン、試行の状態には、worker が付けたラベルではなく control plane の情報を使います。
3. レビュー用ストアは、収集コンポーネントからのアップロードだけを受け入れ、その実行に指定された Lamp のレビュー担当者にだけ読み取りを許可します。作業の依頼者であっても、自動的にレビューへのアクセス権が付くわけではありません。ストアは 2 つのファイルを信頼できないテキストとして表示し、コマンドやパッチ適用の承認としては扱いません。受け入れから 7 日後に、保存した 2 つのファイルを削除します。この例では、バックアップに別のコピーはありません。
4. エクスポートが失敗しても、workspace サービスは `/work` を破棄します。変更されたソース、バイナリ、一時ファイルも含みます。[control plane がそのクリーンアップを確認します](../operations/sandbox-lifecycle.md#what-gets-deleted-and-when)。レビュー用ストアでの有効期限は別に管理します。

ファイル名とサイズを確認しても、テキストの内容を確認したことにはなりません。worker は、読み取れるデータならどちらのファイルにも書き込めます。最初からシークレットや無関係なデータを workspace に含めないでください。

次の [ネットワークの policy](network-policy.md) では、worker がネットワークサービスにアクセスできなくても、それらのファイルをやり取りできる理由を説明します。
