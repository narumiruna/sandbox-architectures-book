# Capability

本書で Capability とは、コードを実行するシステムがアクセスを許可した結果、そのコードが使えるリソースや操作のことです。許可の範囲を知るには、コードが何をできるかと、何を対象にできるかの両方を確認します。ある許可を狭くしても、別の経路でコードが得た広いアクセス権限は取り消されません。

## 例

報告用のスクリプトが [sandbox](sandbox.md) で実行され、特定のプロジェクトの Issue のタイトルを返す [tool](tool.md) を一つだけ使えます。スクリプトに許されるのはタイトルを読むことで、Issue の編集や任意のネットワークリクエストの送信ではありません。呼び出しを処理するサービスは、自身の [credential](credential.md) を使い、スクリプトには渡しません。

## 許可の対象と範囲

[host function](host-function.md) は Issue の検索などの操作を許可できます。読み取り専用の [mount](mount.md) は、ファイルへのアクセスを許可しつつ、その Mount を通じた変更は許可しません。どちらの場合も、Workload の外のコンポーネントが制限を適用します。ツールハンドラーが指定された Issue を確認するか、オペレーティングシステムが読み取り専用アクセスを強制します。

Capability は名前ではなく効果で判断します。「Issue を読む」という名前のツールでも、ハンドラーが指定されたプロジェクトを確認して初めて、そのプロジェクトに範囲を限定できます。一般的なネットワークアクセスと API トークンを持つスクリプトは、ツールを使わずに操作できる場合があります。そのため、[least privilege](least-privilege.md) を適用するときは、直接アクセスとツール経由のアクセスを両方評価します。
