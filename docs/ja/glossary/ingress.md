# Ingress

Ingress は、境界を越えて sandbox に入るネットワークトラフィックです。Ingress の [policy](policy.md) では、内部のサービスへの接続を誰が開始できるかを制御できます。プレビュー URL はブラウザーからサービスへの経路を提供しますが、URL だけでは利用者の身元を確認できません。

## 例

開発者が sandbox 内で Web サーバーを起動し、サイトのプレビューを開きます。Sandbox の外にある gateway は、開発者がサインイン済みか、その sandbox へのアクセス権があるかを確認します。リクエストはプレビュー用の Web サーバーにだけ転送し、サインイン用の [credential](credential.md) は sandbox に渡しません。

## ルーティングとアクセスの確認

Gateway は *reverse proxy* として動作できます。[RFC 9110 の Section 3.7](https://www.rfc-editor.org/rfc/rfc9110.html#section-3.7) にあるように、クライアントから Web リクエストを受け取り、選択したサーバーに転送します。ルーティングは接続先の sandbox とサービスを選びます。Authorization は呼び出し元にその接続が許可されているかを確認します。Gateway でその判断を強制するには、確認を行う経路を通らなければサービスに到達できないようにします。

経路が何を公開し、いつ閉じるかを確認します。プレビュー用の経路で sandbox 内のほかのサービスまで公開する必要はありません。また、セッションが終了したらその経路を閉じます。外部のクライアントが接続を開始した場合でも、プレビューサーバーの応答は [egress](egress.md) トラフィックとして sandbox の外に出ます。
