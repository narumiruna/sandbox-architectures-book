# Least privilege

Least privilege とは、コードにその作業に必要な権限だけを与えることです。実行できる操作、操作の対象、アクセスを許す期間を絞ります。確認すべきなのは設定の記述だけでなく、tool 経由も含め、コードが実際に何にアクセスできるかです。

## 例

依存関係のレポートを作るには、プロジェクトのパッケージマニフェストを読み、バージョン情報を調べる必要があります。[Sandbox](sandbox.md) は、読み取り専用のマニフェストのコピーと、承認済みの registry でバージョンを検索する [tool](tool.md) を公開します。このジョブに workspace への書き込み権限、制限のないネットワーク接続、ジョブ専用の registry token は不要です。

## 権限を一つずつ絞る

まず [workload](workload.md) が必要とする操作を特定します。アクセス対象を必要なファイルに絞り、読み取りと書き込みを分け、特定の tool 操作だけで足りるなら汎用インターフェースよりもそれを優先します。サービスがリクエストを認証する必要がある場合は、再利用可能な秘密情報をコードに渡す代わりに、承認済みのリクエストに [credential injection](credential-injection.md) を使えます。一時的なアクセス権はジョブの終了時に取り消します。

許可した経路を一つずつ確認します。読み取り専用の [mount](mount.md) はその mount 経由の書き込みを防ぎますが、別の tool が同じファイルに書き込むことまでは防げません。Tool の handler は独自に制限を適用する必要があります。Least privilege は workload が影響を与えられる範囲を狭めますが、許可済みの操作による被害までは防げません。
