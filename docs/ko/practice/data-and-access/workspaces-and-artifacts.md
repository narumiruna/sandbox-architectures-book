# Workspace와 artifact {#workspaces-and-artifacts}

Worker는 프로젝트 사본을 수정하고, 검토자에게 필요한 파일만 돌려주도록 합니다. [Lamp 예제](../design/from-issue-to-patch.md)에서 Linux worker는 `/work`에서 수정 사항을 빌드하고 테스트합니다. 검토용으로 텍스트 패치와 테스트 출력을 돌려줄 수 있지만, 수정 사항을 게시할 수는 없습니다.

## Worker가 변경할 수 있는 범위 정하기 {#choose-what-the-worker-can-change}

[workspace](../../glossary/workspace.md)는 작업에서 사용할 수 있는 파일 집합입니다. [mount](../../glossary/mount.md)는 특정 경로에서 파일을 사용할 수 있게 하는 것이며, 반드시 파일을 복사하는 것은 아닙니다. 체크아웃은 저장소에서 선택한 리비전의 소스 트리입니다.

| Workspace 구성 | 원본 체크아웃에 미치는 영향 | 적합한 경우 |
| --- | --- | --- |
| 읽기 전용 mount | Worker는 파일을 읽을 수 있지만 해당 mount를 통해 파일을 변경할 수는 없습니다. 변경 사항을 쓰려면 별도의 쓰기 가능한 위치가 필요합니다. 다른 process는 여전히 원본을 변경할 수 있습니다. | 파일을 살펴보거나 모든 출력을 다른 곳에 쓰는 빌드에 적합합니다. |
| 쓰기 가능한 공유 디렉터리 | 디렉터리가 원본 체크아웃이면 편집, 삭제, 일부만 기록된 내용도 발생하는 즉시 원본에 반영됩니다. 작업이 실패해도 마찬가지입니다. | 변경 사항을 즉시 반영하려는 신뢰할 수 있는 로컬 작업에 적합합니다. |
| 명시적으로 내보내는 일회용 사본 | Worker는 자기 사본만 수정합니다. 원본은 mount되지 않으며 worker가 원본에 쓸 수 있는 다른 경로도 없습니다. 별도의 수집기가 받아들인 결과물만 돌려줍니다. | 소스를 수정해야 하지만 검토 전에는 변경 사항을 적용하면 안 되는 빌드에 적합합니다. |

읽기 전용이라고 해서 비공개인 것은 아닙니다. Worker는 mount를 통해 노출된 모든 파일을 읽을 수 있습니다. 어떤 구성을 선택하든 필요한 입력만 제공하세요. 로컬 설정이나 [credential](../../glossary/credential.md)은 포함하지 마세요.

## `/work` 밖으로 내보낼 파일 정하기 {#decide-what-leaves-work}

[artifact](../../glossary/artifact.md)는 작업이 끝난 뒤에도 보관하기로 한 결과물입니다. Lamp 검토자에게는 `change.patch`(최대 128 KiB)와 `test.log`(최대 64 KiB)만 필요합니다. 이 예제에서 정한 크기 한도는 worker의 디스크 한도와 별개로, 수락할 파일에 적용됩니다.

1. Workspace 서비스는 [control plane](../../glossary/control-plane.md)이 해당 실행에 할당한 내용을 따릅니다. 승인된 리비전의 소스와 테스트, 작업 요약을 `/work`에 mount한 새 [guest](../../glossary/guest.md) 디스크에 복사합니다. 저장소 이력, 설정, 비밀 정보는 복사하지 않으며 원본 체크아웃도 mount하지 않습니다. Worker는 테스트를 포함해 사본을 수정할 수 있습니다.
2. 빌드와 테스트 명령이 성공을 보고하고 worker가 멈추면, worker의 [isolation boundary](../../glossary/isolation-boundary.md) 밖에 있는 수집기가 해당 실행의 디스크에서 지정된 두 파일만 읽습니다. 파일 시스템 링크는 따라가지 않으며, 두 파일 모두 한도 이내의 일반 UTF-8 텍스트 파일일 때만 함께 수락합니다. 파일이 없거나 너무 크거나 유효하지 않으면 일부 출력만 노출하지 않고 결과를 거부합니다. Worker가 제공한 라벨을 신뢰하는 대신 control plane에서 받은 실행 ID, 기준 리비전, 시도 상태를 사용합니다.
3. 검토 저장소는 수집기의 업로드만 받고, 해당 실행에 지정된 Lamp 검토자에게만 읽기를 허용합니다. 요청자라고 해서 자동으로 검토 권한을 얻지는 않습니다. 저장소는 두 파일을 신뢰할 수 없는 텍스트로 보여 줍니다. 명령이나 패치 적용 승인으로 취급하지 않습니다. 수락한 날로부터 7일 뒤에 두 사본을 모두 삭제합니다. 이 예제에서는 백업에 별도 사본을 남기지 않습니다.
4. Workspace 서비스는 내보내기가 실패해도 수정된 소스, 바이너리, 임시 파일을 포함한 `/work`를 폐기합니다. [Control plane은 정리가 끝났는지 확인합니다](../operations/sandbox-lifecycle.md#what-gets-deleted-and-when). 검토 저장소의 보관 기간 만료는 이 정리와 별개입니다.

파일 이름과 크기를 확인해도 텍스트 내용을 검사한 것은 아닙니다. Worker는 읽을 수 있는 데이터를 어느 파일에든 넣을 수 있습니다. 비밀 정보와 작업에 관계없는 데이터는 처음부터 workspace에 넣지 마세요.

다음: [네트워크 policy](network-policy.md)에서는 worker가 네트워크 서비스에 접근하지 않고도 파일을 주고받을 수 있는 이유를 설명합니다.
