# 용어집

이 용어집을 [Sandbox의 격리 경계](sandbox-isolation-boundaries.md), [Agent sandbox 아키텍처](agent-sandbox-architectures.md)와 함께 활용하세요. 용어는 전체 이름을 기준으로 알파벳순으로 정렬했습니다. 이 페이지에서 전체 이름이나 약어로 검색하세요. 예를 들어 `WebAssembly`와 `Wasm`은 같은 항목에 나오며 같은 페이지로 연결됩니다. 각 항목에서는 용어를 설명하고 예를 듭니다.

- **[Agent](glossary/agent.md)** — 모델로 다음 행동을 결정하고 tool을 호출해 실행할 수 있는 시스템입니다. Sandbox 안에는 agent 전체가 들어갈 수도 있고, agent가 생성한 코드만 들어갈 수도 있습니다.
- **[Allowlist](glossary/allowlist.md)** — Policy가 허용하는 자원이나 동작의 목록입니다. 예를 들어 egress allowlist로 외부 연결 대상을 지정된 서비스로 제한할 수 있습니다.
- **[Artifact](glossary/artifact.md)** — 패치나 테스트 보고서처럼 작업이 끝난 뒤에도 보관하기로 한 결과물입니다.
- **[Authorization](glossary/authorization.md)** — 신원이 확인된 호출자가 특정 자원에 대해 어떤 동작을 수행해도 되는지 판단하는 것입니다.
- **[Capability](glossary/capability.md)** — 이 책에서는 host가 허용하여 코드가 사용할 수 있는 자원이나 동작을 뜻합니다. 예를 들어 이슈를 읽는 tool은 일반적인 네트워크 연결을 제공하지 않고도 이슈 조회를 허용할 수 있습니다.
- **[Code Mode](glossary/code-mode.md)** — 모델이 tool을 호출하고 그 결과를 조합하는 프로그램을 작성하는 방식입니다. 프로그램의 격리 방식이 아니라 모델의 tool 사용 방식을 가리킵니다.
- **[Cold boot](glossary/cold-boot.md)** — 실행 중이던 VM의 저장 상태를 복원하는 대신 guest 운영체제를 부팅하여 새 VM을 시작하는 것입니다.
- **[Cold start](glossary/cold-start.md)** — 재사용할 준비가 된 환경이 없을 때 실행 환경을 시작하는 것입니다. 부팅, snapshot 복원 또는 언어 runtime 시작이 필요할 수 있습니다. Cold-start latency는 환경에서 작업할 수 있을 때까지 기다리는 시간입니다.
- **[Container](glossary/container.md)** — 하나 이상의 process를 위한 실행 환경으로, 보통 container image로 만듭니다. Process가 host kernel을 공유할지, user-space kernel을 사용할지, VM 안에서 실행될지는 runtime이 결정합니다.
- **[Container image](glossary/container-image.md)** — Container를 만드는 데 쓰는 파일 시스템과 설정을 묶은 것입니다. Image 자체에는 실행 중인 process의 상태가 들어 있지 않습니다.
- **[Container runtime](glossary/container-runtime.md)** — Image나 미리 준비한 bundle에서 container를 만들어 실행하는 소프트웨어입니다. 설정된 격리를 적용하고 workload의 process를 시작합니다.
- **[Control group (cgroup)](glossary/control-group.md)** — Process를 그룹으로 묶어 CPU나 메모리 등의 자원 사용량을 집계하거나 제한하는 Linux 기능입니다. Cgroup은 파일 시스템이나 네트워크 경계가 아닙니다.
- **[Control plane](glossary/control-plane.md)** — Sandbox를 어디에 배치하고 언제 시작하거나 중지할지 등 관리 결정을 내리는 시스템 구성 요소입니다. 실행 경계가 아닙니다.
- **[CPU privilege level](glossary/cpu-privilege-level.md)** — 프로세서의 접근 권한 수준입니다. x86-64에서는 host와 guest 모두 일반적으로 kernel은 ring 0에서, 애플리케이션은 ring 3에서 실행됩니다.
- **[Credential](glossary/credential.md)** — API token이나 개인 키처럼 신원을 증명하거나 접근을 허용하는 값입니다. Credential을 받은 코드는 의도한 tool 호출 밖에서도 그 값을 사용할 수 있습니다.
- **[Credential injection](glossary/credential-injection.md)** — Workload를 대신하여 요청에 credential을 추가하는 방식입니다. Proxy는 승인된 요청에만 credential을 추가하여 workload 코드가 credential 자체를 받지 않도록 할 수 있습니다.
- **[Egress](glossary/egress.md)** — 환경 밖으로 나가는 네트워크 트래픽입니다. Egress policy는 workload가 접근할 수 있는 목적지나 서비스를 제어합니다.
- **[Engine isolate](glossary/engine-isolate.md)** — V8 같은 언어 엔진 안에서 자체 관리 상태를 갖는 별도의 실행 환경입니다. 운영체제 process나 guest VM은 아닙니다.
- **[Extended Page Tables (EPT)](glossary/extended-page-tables.md)** — Guest 물리 주소를 host 물리 주소에 대응시키는 Intel 프로세서 기능입니다.
- **[Guest](glossary/guest.md)** — VM 안에서 실행되는 운영체제와 프로그램입니다. **guest kernel**은 VM이 그 프로그램에 제공하는 자원을 관리합니다.
- **[Host](glossary/host.md)** — Sandbox 밖에서 자원을 제공하는 시스템입니다. VM의 경우 보통 VM을 실행하는 머신이나 운영체제입니다. 스크립트 sandbox에서는 runtime을 내장한 애플리케이션을 뜻할 수도 있습니다.
- **[Host function](glossary/host-function.md)** — 언어 sandbox 밖에서 구현하여 그 안의 코드에 제공하는 함수입니다. 예를 들어 host는 프로젝트 파일 하나를 읽거나 서비스에 질의하는 함수를 제공할 수 있습니다.
- **[Hypervisor](glossary/hypervisor.md)** — Guest가 머신의 CPU와 메모리를 사용하는 방식을 제어하는 소프트웨어입니다. 프로젝트 문서에서는 *hypervisor*와 *virtual machine monitor*를 같은 뜻으로 쓰기도 합니다. 이 책에서는 VM과 가상 장치를 관리하는 구성 요소를 VMM이라고 부릅니다.
- **[Ingress](glossary/ingress.md)** — 환경 안으로 들어오는 네트워크 트래픽입니다. Sandbox 안의 웹 서버에 접속할 수 있는 미리 보기 URL을 제공하는 것이 ingress를 허용하는 한 방법입니다.
- **[Isolation boundary](glossary/isolation-boundary.md)** — Workload를 자원이나 다른 workload와 분리하는 기술적 장치입니다. 예로 VM 경계나 언어 runtime이 있습니다. 무엇이 경계를 넘을 수 있는지는 policy가 정합니다.
- **[Isolation unit](glossary/isolation-unit.md)** — 같은 경계 하나를 공유하는 workload의 집합입니다. 예를 들어 pod마다 VM을 두면 pod 간에는 격리되지만 같은 pod의 각 container에 별도의 guest kernel이 생기지는 않습니다.
- **[Kernel](glossary/kernel.md)** — 운영체제의 핵심 부분입니다. Process, 메모리, 파일, 장치를 관리하고 프로그램의 요청을 처리합니다.
- **[Kernel-based Virtual Machine (KVM)](glossary/kernel-based-virtual-machine.md)** — VMM이 하드웨어 지원을 받아 guest를 실행할 때 사용할 수 있는 Linux kernel의 가상화 인터페이스입니다.
- **[Least privilege](glossary/least-privilege.md)** — 작업에 필요한 권한만 workload에 주는 원칙입니다. 예를 들어 파일을 확인하기만 하면 되는 workload에는 읽기 전용 workspace를 사용합니다.
- **[Microsoft Hypervisor (MSHV)](glossary/microsoft-hypervisor.md)** — 이를 지원하는 Linux host에서 `/dev/mshv`를 통해 소프트웨어에 제공하는 가상화 backend입니다.
- **[MicroVM](glossary/microvm.md)** — 부가 비용을 줄이도록 설계된 VM입니다. 보통 범용 VM보다 가상 장치가 적지만 guest kernel은 그대로 실행합니다.
- **[Mount](glossary/mount.md)** — 파일 시스템이나 디렉터리에 특정 경로로 접근할 수 있게 하는 것입니다. Bind mount는 기존 host 디렉터리를 복사하지 않고 노출합니다. 쓰기가 가능하면 변경 사항이 host 파일에 즉시 반영될 수 있습니다.
- **[Namespace](glossary/namespace.md)** — Process ID, 파일 시스템 mount, 네트워크 인터페이스 같은 자원이 process마다 별도로 보이게 하는 Linux 기능입니다. Process는 여전히 같은 kernel을 공유합니다.
- **[Native binary](glossary/native-binary.md)** — 특정 CPU와 운영체제 인터페이스용 기계어로 컴파일한 프로그램입니다. Linux native binary는 호환되는 Linux 환경에서 실행할 수 있지만, Wasm 모듈로 직접 실행할 수는 없습니다.
- **[Observability](glossary/observability.md)** — 상태, 타임스탬프, 로그처럼 기록된 증거로 시스템이 무엇을 했는지 파악할 수 있는 능력입니다.
- **[Open Container Initiative (OCI)](glossary/open-container-initiative.md)** — Container image, 배포, runtime의 공개 규격을 관리하는 단체입니다. OCI 호환 여부만으로는 runtime이 어떤 isolation boundary를 쓰는지 알 수 없습니다.
- **[Operating-system process sandbox](glossary/operating-system-process-sandbox.md)** — Host kernel에서 native process를 실행하고 운영체제 기능으로 접근을 제한하는 sandbox입니다. 별도의 guest kernel을 부팅하지 않습니다.
- **[Pod](glossary/pod.md)** — 네트워크 환경을 공유하고 스토리지도 공유할 수 있는 하나 이상의 container를 묶는 Kubernetes 배포 단위입니다. 일부 runtime은 pod마다 별도의 VM을 제공합니다.
- **[Policy](glossary/policy.md)** — Workload에 어떤 동작과 자원 사용을 허용할지 정하는 규칙입니다. 신뢰할 수 있는 구성 요소가 규칙을 적용해야 효력이 있습니다.
- **[Process](glossary/process.md)** — 고유한 상태와 자원 접근 권한을 가진, 실행 중인 프로그램의 인스턴스입니다.
- **[Resident set size (RSS)](glossary/resident-set-size.md)** — Process의 메모리 가운데 현재 물리 메모리에 있는 양입니다.
- **[Resource limit](glossary/resource-limit.md)** — 작업이 사용할 수 있는 메모리, CPU 시간, 디스크 공간 같은 자원의 상한입니다.
- **[Restricted interpreter](glossary/restricted-interpreter.md)** — 지원하는 언어 기능과 내장 기능만 실행하는 프로그램입니다. 코드는 tool 호출처럼 host가 제공하는 동작을 통해 interpreter 밖에 접근합니다.
- **[Runtime](glossary/runtime.md)** — Workload를 실행하거나 실행 환경을 준비하는 소프트웨어입니다. Container runtime과 Wasm runtime은 서로 다른 계층에서 작동하므로 runtime이라는 말만으로는 어떤 경계를 뜻하는지 알 수 없습니다.
- **[Sandbox](glossary/sandbox.md)** — 코드가 접근하거나 영향을 줄 수 있는 대상을 제한하는 실행 환경입니다. 무엇을 격리하는지는 경계, policy, 노출된 자원에 따라 달라집니다.
- **[Sandbox session](glossary/sandbox-session.md)** — Sandbox 서비스가 한 단위로 추적하는 실행 또는 사용 기간입니다. 여러 요청에 걸쳐 workspace와 worker 상태를 유지할 수 있습니다.
- **[Seccomp](glossary/seccomp.md)** — Process의 system call을 필터링할 수 있는 Linux 기능입니다. 자체적으로 파일 시스템 경로에 관한 규칙을 제공하지는 않습니다.
- **[Snapshot](glossary/snapshot.md)** — 나중에 복원할 수 있도록 저장한 시스템 상태입니다. 구현에 따라 디스크 내용, 메모리와 장치 상태, 또는 둘 모두가 들어갈 수 있습니다. 메모리를 포함한 snapshot에는 credential이나 다른 비밀 정보도 들어갈 수 있습니다.
- **[System call (syscall)](glossary/system-call.md)** — 파일을 열거나 process를 만드는 등 프로그램이 kernel에 보내는 요청입니다. User-space kernel은 각 호출을 host kernel에 직접 전달하지 않고도 이 인터페이스를 구현할 수 있습니다.
- **[Tenant](glossary/tenant.md)** — 서비스에서 다른 주체와 workload나 데이터를 분리해 취급하는 사용자, 팀 또는 조직입니다. Tenant와 sandbox session이 반드시 일대일로 대응할 필요는 없습니다.
- **[Tool](glossary/tool.md)** — 이슈 조회나 빌드 실행처럼 agent나 스크립트가 호출할 수 있는 동작입니다. 스크립트 sandbox는 호출할 수 있는 tool을 제한하지만, 각 tool은 자신이 수행할 동작의 권한을 확인해야 합니다.
- **[User space](glossary/user-space.md)** — 애플리케이션과 대부분의 서비스가 실행되는 kernel 바깥의 영역입니다. 애플리케이션은 system call로 kernel에 서비스를 요청합니다.
- **[User-space kernel](glossary/user-space-kernel.md)** — Host kernel 밖에서 운영체제 인터페이스를 구현하는 소프트웨어입니다. 예를 들어 gVisor는 별도의 Linux guest kernel을 부팅하지 않고 Sentry 구성 요소에서 Linux system call을 처리합니다.
- **[Virtual machine (VM)](glossary/virtual-machine.md)** — 자체 운영체제 kernel을 갖춘 가상 컴퓨터입니다. 하드웨어 지원을 받는 VM은 CPU 가상화 기능을 사용해 guest 실행을 host에서 분리합니다.
- **[Virtual machine monitor (VMM)](glossary/virtual-machine-monitor.md)** — 가상 장치를 포함한 VM을 만들거나 관리하는 구성 요소입니다. Firecracker는 VMM입니다. 완전한 agent sandbox는 여기에 workspace, 네트워크, 수명 관리를 추가할 수 있습니다.
- **[VM exit](glossary/vm-exit.md)** — 프로세서가 guest 실행에서 hypervisor로 제어권을 넘기는 전환입니다. Hypervisor는 이벤트를 처리하고 guest 실행을 재개할 수 있습니다.
- **[Warm pool](glossary/warm-pool.md)** — 작업이 도착하기 전에 준비해 둔 sandbox 집합으로, 요청이 전체 설정을 기다리지 않고 sandbox를 할당받을 수 있게 합니다. 어느 단계까지 미리 준비하는지는 플랫폼에 따라 다릅니다.
- **[WebAssembly (Wasm)](glossary/webassembly.md)** — 여러 환경에서 쓸 수 있는 실행 형식입니다. Wasm runtime은 메모리 접근을 확인하고 명시적인 인터페이스를 통해 host 서비스를 노출합니다. Wasm runtime에서 실행된다는 이유만으로 코드에 파일 시스템이나 셸이 제공되지는 않습니다.
- **[WebAssembly System Interface (WASI)](glossary/webassembly-system-interface.md)** — 시계나 파일 접근 같은 동작을 위해 Wasm host가 제공할 수 있는 인터페이스의 모음입니다. WASI를 쓴다고 해서 모든 host 자원을 기본으로 사용할 수 있는 것은 아닙니다.
- **[Windows Hypervisor Platform (WHP)](glossary/windows-hypervisor-platform.md)** — VMM이 하드웨어 지원을 받아 guest를 실행하는 데 사용할 수 있는 Windows API입니다.
- **[Workload](glossary/workload.md)** — Sandbox가 실행하는 코드와 process입니다. 작업에 따라 생성된 스크립트 하나, 빌드 하나 또는 agent session 전체가 workload일 수 있습니다.
- **[Workspace](glossary/workspace.md)** — 작업에서 사용할 수 있는 파일 집합입니다. 예를 들어 체크아웃을 복사한 디렉터리나 mount한 디렉터리가 있습니다.
