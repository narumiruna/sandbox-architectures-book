# Least privilege

Least privilege 是指只授予程式碼完成工作所需的權限。限制程式碼可以做什麼、可以對哪些資源操作，以及可以存取多久。判斷時不能只看設定，還要確認程式碼實際能存取什麼，包括透過工具能存取的資源。

## 範例

產生相依套件報告時，必須讀取專案的套件清單並查詢版本資訊。它的 [sandbox](sandbox.md) 提供唯讀的清單副本，以及用來查詢核准 registry 版本資訊的 [tool](tool.md)。這項工作不需要工作區寫入權限、不受限制的網路連線，也不需要自己的 registry token。

## 縮小每項授權的範圍

先確認 [workload](workload.md) 需要哪些操作。只開放必要的檔案，分開授予讀取和寫入權限；如果某個特定的工具操作就能完成工作，就不要開放通用介面。如果服務必須驗證請求身分，可以對核准的請求使用 [credential injection](credential-injection.md)，而非將可重複使用的機密交給程式碼。工作完成時，終止暫時性的存取權限。

逐一確認每條允許的存取路徑。唯讀 [mount](mount.md) 會阻止透過該 mount 寫入，但無法阻止另一個工具寫入相同檔案。工具的處理程式必須強制執行自己的限制。Least privilege 能縮小 workload 可影響的範圍，但無法防止獲准操作造成損害。
