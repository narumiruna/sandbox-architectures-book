# Capability

在本書中，capability 是指程式碼因執行它的系統授予存取權，而能使用的資源或作業。要瞭解授予的權限，既要問程式碼能做什麼，也要問它能對哪些對象執行這些動作。範圍較小的授權不會取消程式碼透過其他途徑取得的較廣泛存取權。

## 範例

產生報告的指令碼在 [sandbox](sandbox.md) 中執行，可以使用一個 [tool](tool.md) 來傳回特定專案的議題標題。指令碼可以讀取這些標題，但不能編輯議題或任意發出網路請求。處理呼叫的服務使用自己的 [credential](credential.md)，不會將它交給指令碼。

## 授權涵蓋的範圍

[Host function](host-function.md) 可以授予執行議題查詢等作業的權限。唯讀 [mount](mount.md) 可以授予存取檔案的權限，但不允許透過該 mount 變更檔案。在這兩種情況中，限制都由 workload 外部的元件執行：工具處理程式會檢查請求指定的議題，或由作業系統強制執行唯讀存取。

以實際效果而非名稱來判斷 capability。名為「讀取議題」的工具，只有在處理程式會檢查請求指定的專案時，範圍才會限制在該專案內。具備一般網路存取權和 API 權杖的指令碼，可能不需要藉助該工具就能執行動作。因此，應用 [least privilege](least-privilege.md) 時，請同時評估直接存取及透過工具進行的存取。
