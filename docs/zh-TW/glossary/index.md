# 術語表

請搭配 [Sandbox 的隔離邊界](../sandbox-isolation-boundaries.md)和 [Agent sandbox 架構](../agent-sandbox-architectures.md)使用本表。術語依英文全名的字母順序排列。查找術語時，可以在本頁搜尋全名或縮寫。例如，`WebAssembly` 和 `Wasm` 在同一個條目中，連到同一頁。每個條目都會說明術語並提供範例。

- **[Agent](agent.md)** — 使用模型決定下一步，並且可以呼叫 tool 來執行動作的系統。Sandbox 可以容納整個 agent，也可以只執行 agent 產生的程式碼。
- **[Allowlist](allowlist.md)** — Policy 允許使用的資源或允許執行的動作清單。例如，egress allowlist 可以讓對外連線只能連到指定的服務。
- **[Artifact](artifact.md)** — 工作完成後選擇保留的輸出，例如修補程式或測試報告。
- **[Authorization](authorization.md)** — 判定已知身分的呼叫端是否可以對特定資源執行某項動作。
- **[Capability](capability.md)** — 本書指 host 授予程式碼使用的資源或操作。例如，讀取問題單的 tool 可以開放這項操作，而不提供一般網路連線。
- **[Code Mode](code-mode.md)** — 由模型撰寫程式，再由該程式呼叫 tool 並整合其結果的模式。這個術語描述模型如何使用 tool，而不是程式如何隔離。
- **[Cold boot](cold-boot.md)** — 啟動新 VM 時，啟動其 guest 作業系統，而不是還原先前儲存的 VM 執行狀態。
- **[Cold start](cold-start.md)** — 沒有可直接重用的執行環境時，建立可用的環境。這可能涉及開機、還原 snapshot，或啟動程式語言的 runtime。Cold-start latency 是開始工作前的等待時間。
- **[Container](container.md)** — 供一或多個 process 使用的執行環境，通常由 container image 建立。由 runtime 決定這些 process 是共用 host kernel、使用 user-space kernel，還是在 VM 裡執行。
- **[Container image](container-image.md)** — 打包好的檔案系統與設定，用來建立 container。Image 本身不含 process 當下的執行狀態。
- **[Container runtime](container-runtime.md)** — 依據 image 或事先準備的套件組合來建立與執行 container 的軟體。它套用指定的隔離設定，並啟動 workload 的 process。
- **[Control group (cgroup)](control-group.md)** — Linux 用來將 process 分組的機制，可統計或限制 CPU 和記憶體等資源用量。Cgroup 不是檔案系統或網路的隔離邊界。
- **[Control plane](control-plane.md)** — 系統中負責管理決策的部分，例如決定將 sandbox 放在哪裡，以及何時啟動或停止它。它不是執行邊界。
- **[CPU privilege level](cpu-privilege-level.md)** — 處理器的存取權限等級。在 x86-64 上，無論是 host 還是 guest，kernel 通常在 ring 0 執行，應用程式則在 ring 3 執行。
- **[Credential](credential.md)** — 可用來證明身分或取得存取權的值，例如 API token 或私密金鑰。收到 credential 的程式碼可能在原定的 tool 呼叫之外使用它。
- **[Credential injection](credential-injection.md)** — 代替 workload 將 credential 加入請求。Proxy 可以只在獲准的請求中加入它，這樣 workload 的程式碼便不會收到 credential 本身。
- **[Egress](egress.md)** — 從環境送出的網路流量。Egress policy 控制 workload 能連到哪些目的地或服務。
- **[Engine isolate](engine-isolate.md)** — V8 等程式語言引擎內的獨立執行環境，有各自受管理的狀態。它不是作業系統的 process，也不是 guest VM。
- **[Extended Page Tables (EPT)](extended-page-tables.md)** — Intel 處理器將 guest 的實體位址對應到 host 的實體位址的機制。
- **[Guest](guest.md)** — 在 VM 內執行的作業系統及程式。**Guest kernel** 管理由 VM 開放給這些程式的資源。
- **[Host](host.md)** — 在 sandbox 外部並提供資源的系統。對 VM 來說，通常是執行 VM 的機器或作業系統；對指令碼的 sandbox 來說，也可以是內嵌 runtime 的應用程式。
- **[Host function](host-function.md)** — 在程式語言的 sandbox 外部實作、供內部程式碼呼叫的函式。例如，host 可以提供讀取單一專案檔案或查詢服務的函式。
- **[Hypervisor](hypervisor.md)** — 控制 guest 如何使用機器的 CPU 和記憶體的軟體。專案文件有時會將 *hypervisor* 和 *virtual machine monitor* 當成同義詞；本書用 VMM 指管理 VM 及其虛擬裝置的元件。
- **[Ingress](ingress.md)** — 進入環境的網路流量。為 sandbox 內的網頁伺服器提供預覽 URL，就是允許 ingress 的一種方式。
- **[Isolation boundary](isolation-boundary.md)** — 將 workload 與資源或其他 workload 分隔開的技術機制，例如 VM 邊界或程式語言的 runtime。哪些東西可以跨越邊界，由 policy 決定。
- **[Isolation unit](isolation-unit.md)** — 共用同一個邊界實例的一組 workload。例如，每個 pod 配一台 VM 可以隔離不同 pod，但同一個 pod 裡的 container 不會因此各有自己的 guest kernel。
- **[Kernel](kernel.md)** — 作業系統的核心。它管理 process、記憶體、檔案和裝置，並處理程式送出的請求。
- **[Kernel-based Virtual Machine (KVM)](kernel-based-virtual-machine.md)** — Linux kernel 提供的虛擬化介面，VMM 可以透過它執行使用硬體輔助虛擬化的 guest。
- **[Least privilege](least-privilege.md)** — 只授予 workload 完成任務所需的權限。例如，只需檢查檔案時，就使用唯讀的 workspace。
- **[Microsoft Hypervisor (MSHV)](microsoft-hypervisor.md)** — 在支援的 Linux host 上，透過 `/dev/mshv` 提供軟體使用的虛擬化後端。
- **[MicroVM](microvm.md)** — 為減少額外開銷而設計的 VM，通常比通用 VM 提供更少的虛擬裝置，但仍然會執行 guest kernel。
- **[Mount](mount.md)** — 讓檔案系統或目錄可以透過某個路徑存取。Bind mount 不必複製 host 上的現有目錄，就能開放存取。如果掛載點可寫入，變更可能會立刻影響 host 上的檔案。
- **[Namespace](namespace.md)** — Linux 的一種機制，讓 process 看到各自的資源範圍，例如 process ID、檔案系統的掛載點或網路介面。這些 process 仍然共用同一個 kernel。
- **[Native binary](native-binary.md)** — 針對特定 CPU 和作業系統介面編譯成機器碼的程式。Linux native binary 可以在相容的 Linux 環境中執行，不能直接當作 Wasm 模組執行。
- **[Observability](observability.md)** — 從狀態、時間戳記和日誌等記錄，了解系統做過什麼的能力。
- **[Open Container Initiative (OCI)](open-container-initiative.md)** — 維護 container image、發佈和 runtime 開放規格的組織。相容於 OCI 並不代表採用特定的 isolation boundary。
- **[Operating-system process sandbox](operating-system-process-sandbox.md)** — 直接在 host kernel 上執行原生 process，並使用作業系統機制限制其存取範圍的 sandbox。它不會啟動獨立的 guest kernel。
- **[Pod](pod.md)** — Kubernetes 的部署單位，包含一或多個 container。這些 container 共用網路環境，也可以共用儲存空間。有些 runtime 會為每個 pod 配置一台 VM。
- **[Policy](policy.md)** — 訂定 workload 可以執行哪些動作、使用哪些資源的規則。只有可信任的元件強制執行時，規則才會生效。
- **[Process](process.md)** — 正在執行的程式實例，有自己的狀態，也有各自可存取的資源。
- **[Resident set size (RSS)](resident-set-size.md)** — Process 目前留在實體記憶體中的記憶體用量。
- **[Resource limit](resource-limit.md)** — 一項工作可使用的資源上限，例如記憶體、CPU 時間或磁碟空間。
- **[Restricted interpreter](restricted-interpreter.md)** — 只執行受支援的語言功能與內建項目的程式。程式碼透過 host 提供的操作（例如呼叫 tool）存取直譯器以外的資源。
- **[Runtime](runtime.md)** — 執行 workload 或為它設定執行環境的軟體。Container runtime 和 Wasm runtime 在不同層運作；單說 runtime 並不能指出是哪一種邊界。
- **[Sandbox](sandbox.md)** — 限制程式碼可存取或影響範圍的執行環境。隔離範圍取決於其邊界、policy 和開放的資源。
- **[Sandbox session](sandbox-session.md)** — Sandbox 服務視為單一單位追蹤的一次執行或一段使用期間。它可以跨請求保留 workspace 和 worker 的狀態。
- **[Seccomp](seccomp.md)** — Linux 的一項功能，可篩選 process 發出的 system call。它本身不提供檔案系統的路徑規則。
- **[Snapshot](snapshot.md)** — 系統可以在日後還原的已儲存狀態。依實作方式而定，可能包含磁碟內容、記憶體與裝置狀態，或兩者都有。含有記憶體內容的 snapshot 也可能含有 credential 或其他機密資料。
- **[System call (syscall)](system-call.md)** — 程式送給 kernel 的請求，例如開啟檔案或建立 process。User-space kernel 可以實作這套介面，不必把每個呼叫直接轉送給 host kernel。
- **[Tenant](tenant.md)** — 使用者、團隊或組織，服務會將其 workload 或資料與其他對象分開。Tenant 和 sandbox session 不必是同一個單位。
- **[Tool](tool.md)** — Agent 或指令碼可呼叫的操作，例如查詢問題單或執行建置。指令碼的 sandbox 限制它能呼叫哪些 tool，而每個 tool 仍須各自判定是否允許執行所要求的動作。
- **[User space](user-space.md)** — 應用程式和大多數服務在 kernel 以外執行的空間。應用程式透過 system call 向 kernel 要求服務。
- **[User-space kernel](user-space-kernel.md)** — 在 host kernel 之外實作作業系統介面的軟體。例如，gVisor 在 Sentry 元件中處理 Linux system call，不必另行啟動 Linux guest kernel。
- **[Virtual machine (VM)](virtual-machine.md)** — 有自己的作業系統 kernel 的虛擬電腦。使用硬體輔助虛擬化的 VM 透過 CPU 的虛擬化功能，將 guest 的執行與 host 分開。
- **[Virtual machine monitor (VMM)](virtual-machine-monitor.md)** — 建立或管理 VM 及其虛擬裝置的元件。Firecracker 是一種 VMM；完整的 agent sandbox 可以在它之外加上 workspace、網路和生命週期管理功能。
- **[VM exit](vm-exit.md)** — 處理器從執行 guest 切換至 hypervisor。Hypervisor 可以處理事件，再繼續執行 guest。
- **[Warm pool](warm-pool.md)** — 在工作到來前就準備好的一組 sandbox，讓請求不用等到整個環境設定完畢才取得可用的 sandbox。提前準備到什麼程度取決於平台。
- **[WebAssembly (Wasm)](webassembly.md)** — 可攜的可執行格式。Wasm runtime 會檢查記憶體存取，並透過明確的介面開放 host 服務。Wasm 程式碼不會只因為在 Wasm runtime 中執行，就取得檔案系統或 shell。
- **[WebAssembly System Interface (WASI)](webassembly-system-interface.md)** — Wasm host 可提供的一系列介面，例如用於存取時鐘或檔案。提供 WASI 不代表預設就能使用 host 的所有資源。
- **[Windows Hypervisor Platform (WHP)](windows-hypervisor-platform.md)** — Windows 提供的 API，VMM 可以透過它執行使用硬體輔助虛擬化的 guest。
- **[Workload](workload.md)** — Sandbox 執行的程式碼與 process。視任務而定，可能是一段產生的指令碼、一次建置，或一整個 agent session。
- **[Workspace](workspace.md)** — 一項工作可使用的一組檔案，例如從版本控制系統取出的專案副本，或掛載的目錄。
